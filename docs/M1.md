# M1：A→B 顺序 SFT pilot

状态：2026-11-18 完成（单 seed）。结果见 reports/m1/SUMMARY.md：AG 学会（val +20.8 pp），学 DBpedia 后 AG 未下降（AB_seq +1.7 pp，replay +0.3 pp），即本设定下未见遗忘。运行 `uv run bash scripts/run_m1.sh`，配置见 `configs/m1.json`。

## 目的

按 [PROPOSAL](PROPOSAL.md) 跑通“数据 → 顺序 SFT → 全任务评测 → 遗忘指标”证据链，并初看 10% replay 能否减少遗忘。单 seed，不作正式结论；M2 再扩到 A→B→C 与 3 seeds。

## 设计

| 项 | 设定 |
|---|---|
| 模型 | Qwen2.5-1.5B-Instruct，BF16 |
| 任务 | A = AG News（4 类），B = DBpedia-14（14 类，标签用自然拼写，如 Office Holder） |
| 数据 | 每任务 train 5000 / val 500 / test 1000，按类均衡；val 取自官方 train，test 取自官方 test；标准化文本去重，官方 test 全部文本禁止进入 train/val |
| LoRA | r=16、alpha=32、dropout=0.05，attention+MLP 投影；同一 adapter 跨阶段延续 |
| 训练 | 每阶段 312 步（有效 batch 16，约 1 epoch）、LR 1e-4、constant+3% warmup；每阶段重置优化器与调度器；只对标签+EOS 计 loss |
| Run | `A`：底座学 AG；`AB_seq`：A 终点学 DBpedia；`AB_replay10`：同上，10% 样本位换成 AG replay |
| Replay | buffer 500 条，从 AG train 按类分层；第 k 个样本位当 ⌊(k+1)·0.1⌋>⌊k·0.1⌋ 时取 replay，精确 10%；新任务样本顺序与 AB_seq 相同，总步数相同 |
| 评测点 | 底座；每阶段 25/50/75/100%（78/156/234/312 步） |

两个 B run 共享同一个 A 阶段，A 只训练一次。LR 未调参，沿用 Stage2 中 LoRA 1e-4 能学会 AG 的设定。

## 评测

每个评测点在两个任务的 test 和 val 上都评：

- 主指标：标签似然准确率，对“标签+EOS”求总 log prob 取最大；另报按 token 归一化的结果。
- 自由生成：greedy，最多 16 token，必须与标签完全一致，否则记为非法输出。
- 另报 macro-F1、格式合法率、gold 标签 NLL 和混淆矩阵。

报告给出：R 矩阵；A 的遗忘 F = R[A,A] − R[B,A]（两任务时 BWT = −F）；B 学习量；配对 bootstrap 95% CI（只量化测试样本不确定性）。

学习检查（工程判据）：A 阶段后 AG val 标签似然准确率至少 +5 pp。

## 底座结果（test / val，标签似然准确率）

AG 70.1 / 71.6；DBpedia 82.2 / 80.0。

## 时间与磁盘

实测底座评测约 3.2 分钟/点。预计 3 次训练约 25 分钟，13 个评测点约 45 分钟，总计约 1.2 小时。adapter 每个 71MB，共约 0.9GB；磁盘低于 3GiB 时停止。
