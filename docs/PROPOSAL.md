# 提案：单卡上复现 LLM 持续 SFT 的灾难性遗忘

## 1. 研究范围

建议做一项小模型、严格控制的现象复现研究：模型学习新任务时，已经获得的旧任务能力如何退化，经验回放能否改善稳定性与可塑性的权衡。

这里的 forgetting 指 catastrophic forgetting。post-training 范围很大，本项目首先覆盖 SFT 的数据、模板、loss mask、优化、checkpoint、评估和持续学习；DPO/RLHF 留作后续独立实验。

目标是达到论文式实验严谨度，不承诺发表，也不把更换模型/缩小数据后的实验称为原论文数值复现。论文参照为 TRACE 与 Luo 等的遗忘实证研究，主实验是受其启发的资源适配设计。

## 2. 研究问题与预注册假设

- H1：顺序训练 A→B→C 后，至少部分已学任务在独立测试集上下降，同时当前任务确实学到新能力。
- H2：固定训练预算下，旧数据 replay 能减少遗忘；可能牺牲新任务学习速度。
- H3：任务顺序影响遗忘；自然语言生成失分可能包含格式漂移，需要与内容能力区分。

假设允许被否定。无明显遗忘也是结果，不用测试集选最容易出现遗忘的设置。

## 3. 模型与训练路线

主模型：Qwen/Qwen2.5-1.5B-Instruct。已有指令能力、体量适合单卡、便于研究后续 SFT 对现有能力的影响。固定 Hugging Face revision 与官方 chat template。

主训练：BF16、同一个 LoRA adapter 连续更新，r=16、alpha=32、dropout=0.05，作用于 attention 和 MLP 的线性投影；不在任务间切换/重建 adapter。避免把“换了 adapter”误判为遗忘。冻结的底座仍可被 adapter 的行为干扰；因此 LoRA 实验不支持“底座权重被擦除”的结论。

初始建议：序列长度 512，micro batch 1–2，gradient accumulation 达有效 batch 16；gradient checkpointing；原生 SDPA；AdamW；LoRA 学习率候选 5e-5、1e-4、2e-4；warmup 3%，gradient clip 1.0。每阶段优化器/调度器统一重置，adapter 延续；replay 对照使用相同策略。只对 assistant response（含 EOS）计算训练 loss，验证 padding、模板、截断与 mask。

显存规划估计 8–16 GiB，未测量，长词表 logits 等会增加峰值。先做完整 optimizer step，显存预算上限约 22 GiB，预留余量。

补充证据：若主实验顺利，在 Qwen2.5-0.5B-Instruct 上做 BF16 全参顺序 SFT 和 replay 对照，使用独立较低 LR 校准。这能检验现象是否局限于 adapter，但不能把模型大小效应与微调方式效应混为一谈。1.5B 全参标准 AdamW 加激活在 24GB 上余量不足，不作为首发路线；7B QLoRA 放后续。

## 4. 数据与学习阶段

第一层：教学 pilot，A=AG News 新闻主题分类，B=DBpedia-14 实体分类。使用自然语言任务描述与真实语义标签，明确任务身份；避免故意冲突的随机标签任务。用来跑通数据→SFT→评估，不作为完整论文证据。

第二层：正式 A/B/C 三任务，A=AG News、B=DBpedia-14、C=Yahoo Answers Topics。不同标签集、相同生成式分类协议。候选数据源分别为 Hugging Face 的 ag_news、dbpedia_14、yahoo_answers_topics；实施前确认维护方、schema、revision、许可证与下载可用性，若替换需先修订协议。

每任务：训练 5000 条、验证 500 条、测试 1000 条，类别分层。验证从官方训练划分抽取；测试只从官方测试划分取，最终冻结。按类别等比例抽样、保存样本 ID 与 hash；同一数据 manifest 用于各 seed 和方法。标准化文本去重并检查跨划分泄漏；同源内容不跨划分。预算按每阶段最多 2 epochs，阶段中 25/50/75/100% 存评估点。另存官方数据统计与截断比例。

5000 是起始规模：仅在 pilot/验证阶段决定是否增加至 10000，冻结后完整重跑所有可比较方法。不得针对最终测试下降幅度改训练量。

第三层：泛化与边界。固定一小套独立通用探针，例如 ARC-Easy/ARC-Challenge（与主训练数据去重核验），用选择题对数似然打分，不依赖 API judge。主实验不能代表数学、代码、多语种或全部通用知识；后续可按 TRACE 官方任务扩展，作为单独里程碑，不冒称已复现完整 TRACE。

可选受控补充：训练后生成的合成实体事实集，配 held-out 问法，检测新增事实的保持；单独报告，不与自然任务混合。

## 5. 实验矩阵

所有方法从相同初始模型开始：

| 方法 | 用途 |
|---|---|
| Frozen initial | 建立未训练能力基线 |
| Sequential SFT，无 replay | 主要遗忘对象 |
| Sequential SFT，10% replay | 核心缓解对照 |
| Joint shuffled SFT | 同预算多任务参考，非数学意义上界 |
| Independent single-task SFT | 分别学 A/B/C，检查每个任务可学习性 |

replay 内存最多 500 个历史样本，按已见任务/类别分层抽样；阶段 A 无 replay。每个后续阶段 batch 中 90% 新任务、10% 历史任务，历史样本只能来自训练集，分数比例通过跨 batch 累计实现。保存 buffer ID 和每类曝光次数。测试与验证数据不进入 buffer。

主比较固定总优化步与总 token 上限，replay 替代部分新任务样本，因此明确报告新/旧 token 数。补充“新数据曝光匹配”比较会额外消耗算力，单列结果，避免把增加算力的收益当作方法收益。

主结果顺序 A→B→C，seeds 17/42/2026。独立单任务基线也用 3 seeds。顺序敏感性用 B→C→A、C→A→B，比较 sequential 与 replay，各 3 seeds。预算不足时先完成主结果，再扩展；不同完成等级清楚标注。

消融优先级：replay 0/5/10/20%（主顺序）；LoRA rank 8/16/32；最后再考虑更多模型。每项改变需报告训练预算及新数据曝光量。

## 6. 评估与指标

每个阶段及中间点均评估所有任务，包括未学任务，形成完整 R 矩阵。R[t,i] 为训练完阶段 t 后在任务 i 上的分数，R[0,i] 为初始分数。主指标 constrained label likelihood accuracy：对完整候选标签序列按固定规则打分（含多 token 标签，主协议用总 log probability），固定模板；报告标签 token 长度并以长度归一化作为敏感性检查。

同时报告自由生成 accuracy、macro-F1、格式合法率、类别混淆矩阵、gold label NLL。自由生成 greedy，固定 max_new_tokens，固定规范化规则；不合法输出按错误计，不静默丢弃。

主报告：
- 最终平均分 AA = mean_i R[T,i]。
- 遗忘 F = mean_(i<T) [max_(t=i,...,T-1) R[t,i] - R[T,i]]，最大值只取阶段末；保留负值表示后续提升，不强行截成零。
- BWT = mean_(i<T) [R[T,i] - R[i,i]]。
- 新任务学习量：R[i,i]-R[i-1,i]，同时给出相对初始值的提升。
- 通用探针初始到最终的分差，单独报告。

使用百分点而非含混的百分比。汇报每个 seed、均值与样本标准差；3 seeds 的统计效力有限。对相同测试样本作 paired bootstrap 95% CI，并明确它主要量化测试样本不确定性，不能替代多 seed。不能把每条测试样本当独立训练重复。

“学过后掉分”需满足：A 阶段独立测试能力提升；后续新任务在学习；固定旧测试下降且超过明显噪声。pilot 验收以验证集 A 至少提升约 5 个百分点为学习检查，目标观察旧任务下降约 5 个百分点以上；这些是工程判据，不是保证或通用灾难性遗忘定义。正式结论看效应大小、CI、seed 一致性和对照，不按一条阈值判定。

若自由生成下降、label likelihood 稳定，优先解释为格式/指令遵循漂移；若两者均降且 NLL 变差，旧任务可访问性能退化的证据更强。都不能证明知识被永久删除。可加 adapter disable 恢复实验与固定少量旧数据再学习实验，作为可访问性和恢复成本诊断。

## 7. 预期结果（假设，非测量）

期望看到：每个新任务训练后本任务表现升高，无 replay 的旧任务曲线出现下滑；replay 曲线更平缓，联合训练平均保持更好。LoRA 小模型上可能只有轻微下降，甚至正迁移。

可用于资源决策的宽范围假设：旧任务下滑 0–30 个百分点，replay 有机会收回部分下降。这个范围没有来自本机的统计依据，不能作为预测区间或论文数值引用。不预填 accuracy 表、不承诺必然出现大幅遗忘。

若未见遗忘：先检查 A 是否真正学会、训练更新是否发生、是否错误加载 checkpoint，以及评分是否被格式影响；然后按预先限定的验证 LR/数据量校准。冻结后报告无遗忘结果；更大 LR 的 stress test 另列，不能替换正常训练结果。

## 8. 时间与资源预算

目前只有 GPU 运算检查，没有吞吐实测。以下为工程预留，不是性能测定：
- 环境、数据审计、100 optimizer steps 基准：约半天；
- 两任务 pilot：约 2–6 GPU 小时；
- 三任务主矩阵：约 24–72 GPU 小时；
- 顺序、replay 比例与 0.5B 全参补充：总量可能扩展至 3–7 天，必要时更长。

基准记录实际非 padding tokens/s、optimizer steps/s、生成评估速度与峰值显存，用“实际训练 token 数/实测吞吐 + 评估时间 + 保存开销”重估。长文本与评估可能成为主要时间开销。

磁盘目标总占用小于 35 GiB，保留至少 10 GiB 空闲：1.5B BF16 底座约 3.1GB；adapter、训练状态、缓存、环境及报告其余空间按实际监控。底座只缓存一份；阶段保存 adapter，不重复保存底座。保留一个可恢复训练 checkpoint，关键阶段保留轻量 adapter 与元数据；清理前按明确 retention 规则执行。0.5B 补充实验前重新检查空间。全部模型/数据缓存指定在当前项目内。

## 9. 分阶段交付

M0：环境锁定、数据 manifest、评分单元检查、100-step 吞吐/显存报告；发现 mask 或数据问题先修复。
M1：A→B pilot，提供原始回答、旧任务曲线与 frozen 对照，验证证据链。
M2：正式三任务 × 三 seeds、replay/joint/独立任务基线，完整结果矩阵。
M3：顺序与比例消融、0.5B 全参补充、误差分析，形成论文式报告。

最终产物：可一条命令重跑的数据准备/训练/评估入口、锁定环境、全部配置与运行命令、数据与模型版本、逐样本预测、JSON/CSV 指标、置信区间、热力图、遗忘曲线、训练 loss/显存/耗时，以及失败运行记录。预先定义的分析与事后探索分开。图和表全部由真实结果生成。

规划目录：configs/、src/、scripts/、data/、artifacts/、results/、reports/；本轮只建立提案文件，不提供未验证训练脚本。
